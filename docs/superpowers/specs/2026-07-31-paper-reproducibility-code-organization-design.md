# Paper Reproducibility and Compatible Code Organisation Design

## Goal

Make the GitHub repository reproduce the thesis's formal analysis while
preserving the old numbered entry points used by local and cluster workflows.
Correct confirmed code--paper inconsistencies without changing the simulated
EEG observations, fitted BGAMs, or the scientific model specification.

## Formal Analysis Contract

The repository's formal pipeline is the paired-radius analysis with:

- radius rules `1sd`, `half-max`, and `2sd`;
- high between-participant heterogeneity;
- 20 participants and 20 trials per participant and condition;
- one stochastic base per replicate, shared by all three radius variants;
- hard spatial truncation with 5, 9, and 21 active electrodes;
- participant-specific truncated temporal waveforms with onset support from
  140 to 180 ms;
- reference timing estimands of 160 ms onset and 342 ms offset;
- a 100 Hz timing-scoring grid from 160 to 340 ms inclusive;
- a BGAM with P-spline margins, `k = c(16, 12)`, `full = FALSE`, four chains,
  3,000 iterations, and 1,000 warmup iterations;
- `eeg_mean | se(eeg_sem, sigma = TRUE)` measurement-error modelling; and
- the current model formula, default priors, posterior-odds rules, SESOI,
  cluster-mass, TFCE, and detection rules.

These settings live in one R configuration module. Pipeline modules, Slurm
entry points, tests, README, and PROJECT_GUIDE consume or reproduce this
contract rather than redefining it independently.

## Ground-Truth Semantics

Spatial and temporal support have different meanings.

The spatial Gaussian is hard-truncated at the selected radius. Every
participant's effect is exactly zero at electrodes outside that radius for all
times. Spatial false positives at 250 ms therefore occur at locations whose
generated truth is exactly zero.

Each participant's temporal waveform is a finite, zero-padded truncated
Gaussian shifted to that participant's sampled onset. There is no second
operation that clips all shifted waveforms to a common 160--342 ms interval.
Consequently, the population mean may have small non-zero tails outside the
reference interval. This follows the simulation design of Nalborczyk and
Buerkner and of the underlying Rousselet onset simulation.

The ground-truth object exposes two explicit continuous fields:

- `theoretical_effect`: the fixed population expectation over the 21 equally
  likely onset values and the mean-preserving amplitude distribution;
- `realised_effect`: the finite-sample field generated by the 20 participants
  drawn in a particular replicate.

For compatibility, `continuous_effect` remains a deprecated alias of
`realised_effect`. Likewise, `population_mean_waveform` remains temporarily as
a deprecated alias of the correctly named `realised_mean_waveform`. New
pipeline code must request an estimand explicitly and may not rely on either
deprecated alias.

Theoretical truth is the primary target for cross-replication amplitude
recovery, RMSE, MAE, projection recovery, and map comparisons. Realised truth
is used for conditional diagnostics such as empirical-minus-injected-signal
residuals. The fixed 160--342 ms interval is a timing/scoring estimand, not the
exact support of the theoretical population field.

Full spatio-temporal binary metrics must be described as scoring-window
metrics. A detection outside the timing interval is an outside-window or
label-based false positive and need not have continuous truth exactly equal to
zero. Metrics whose interpretation requires exact zero truth, including
leakage, determine zero cells from the selected continuous truth field rather
than from membership in the timing-scoring set. The existing 250 ms spatial
FPR and leakage definitions remain valid.

## Module Structure

The formal implementation is organised as:

```text
code/
|-- config/
|   `-- paper_config.R
|-- pipeline/
|   |-- simulation.R
|   |-- generate_montecarlo.R
|   |-- fit_bgam.R
|   |-- fit_paired_radius.R
|   |-- compare_methods.R
|   `-- aggregate_results.R
|-- truth/
|   |-- ground_truth.R
|   `-- migrate_ground_truth.R
|-- reporting/
|-- diagnostics/
|-- sensitivity/
|-- pilot/
|-- exploratory/
`-- archive/
```

The formal pipeline modules provide functions and contain no implicit
top-level run. Numbered files at their current paths remain compatibility
entry points. They source the new modules, preserve current public function
names and environment-variable behaviour, and invoke a `main()` function only
when executed directly. Existing Slurm commands therefore continue to work.

The paired-radius fitting interface accepts both `radius_rule` and `seed`.
Seed 1 remains the current pilot invocation, while the same interface supports
later Monte Carlo array tasks without cloning another fitting script.

Current supporting scripts are classified by purpose instead of deletion:

- figures and thesis tables go under `reporting/`;
- sampler, residual, and fit investigations go under `diagnostics/`;
- threshold, alpha, basis, and SESOI probes go under `sensitivity/`;
- reduced-scope data generation and one-replicate orchestration go under
  `pilot/`;
- one-off research probes go under `exploratory/`;
- superseded single-radius workflows go under `archive/`.

Compatibility entry points are retained wherever an existing local, Slurm, or
documented command refers to the old path. No running Umea or Dortmund job is
updated, cancelled, or otherwise touched by the reorganisation.

## Data and Migration

The migration may add or rename ground-truth fields but must not alter:

- any `sim_*.rds` object;
- participant draws;
- noise realisations;
- spatial weights;
- the realised continuous effect;
- fitted BGAM objects; or
- model configuration files belonging to running fits.

Before modifying an existing ground-truth file, the migration creates a
backup, records stable-field hashes, validates the expected scenario/radius,
and writes through a temporary file followed by atomic replacement. Existing
fits do not need to be rerun. Derived evaluations that select a changed or
newly explicit estimand must be recomputed from the saved fits.

## Paper and Documentation Corrections

The thesis must remove the mean-plus-one-standard-deviation definition of the
temporal active set. It must state that 160 and 342 ms are reference timing
estimands inherited from the truncated-Gaussian template, while onset
heterogeneity gives the population mean small tails outside that interval.

The thesis must distinguish theoretical population truth from finite-sample
realised truth, identify which target each metric uses, and avoid claiming
that all outside-window temporal detections occur where the continuous truth
is exactly zero. Spatial hard truncation and the 5/9/21 active-electrode counts
remain unchanged.

README and PROJECT_GUIDE must describe the paired-radius high-heterogeneity
pipeline, `k = c(16, 12)`, P-spline bases, `sigma = TRUE`, current directories,
and the compatibility layout. Old pilot results may remain only when labelled
as historical results rather than current formal settings.

## Verification

The implementation is protected by deterministic R tests for:

- the single formal configuration contract;
- 5/9/21 active electrodes and exact spatial zeros;
- one seed call and identical stochastic bases across radii;
- fixed timing estimands and the 160--340 ms analysis grid;
- participant-specific temporal zero padding without common-window clipping;
- theoretical truth invariance across replicate-specific participant draws;
- realised truth equality with the injected finite-sample signal;
- compatibility-entry-point parity with the new modules;
- unchanged simulated-data hashes during ground-truth migration; and
- agreement between the local thesis source and the formal configuration when
  `THESIS_TEX` points to the thesis file.

All existing tests must continue to pass. Source parsing, shell syntax checks,
and a fresh one-replicate generator validation run are required before the
work is considered complete. No BGAM is refitted as part of this change.

## Version-Control and Deployment Safety

The existing dirty worktree contains user-owned work and is preserved. Changes
are committed in narrow groups: contract/tests, truth modules, pipeline
modules and wrappers, documentation/thesis, and migration evidence. No push is
performed without explicit approval. Cluster repositories are updated only
after their running jobs finish and after local compatibility tests pass.
